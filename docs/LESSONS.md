# Lessons

What went wrong, and the rule that follows. The agent reads this at the start of every run.

- 2026-11-04: Parallel headless Chromes sharing a profile crash, and Chrome exits non-zero after writing a good PNG. Every render gets its own profile, and the file on disk decides success.
- 2026-11-04: `zoompan` emits frames per input frame, so looped stills made an 8-shot preview run 30.4 s, over Apple's limit. Feed each still once.
- 2026-11-04: Reinstalling the engine reloaded the job and killed a run in progress. install.sh leaves a running job alone.
- 2026-11-04: Discovery counted linked worktrees as separate apps. It now skips any folder whose `.git` is a file. There is a test.
- 2026-11-05: An iPad preview video was built from iPhone screens for an iPhone-only app and queued for upload. The target now needs the manifest's `ipad` flag, and push checks it too. There is a test.
- 2026-11-05: Status can show an app as rejected but not why. Rejection text is readable only signed in to App Store Connect, so check every app's thread before deciding one app's next step.
- 2026-11-09: A run recaptured Moon Club for 0.16.1 in `moon-club-lobby` and stopped before committing, so the next run saw "inputs changed" with nothing pushed. Before recapturing, check `git worktree list` for an unfinished `lobby/*` branch and finish it.
- 2026-11-09: The `cover` sticker sits at a fixed spot over the device's top right. On iPad it hid 17-0's "1 in 6,000" stat. Read the iPad cover too, and drop the badge when it hides something that matters.
- 2026-11-10: Moon Club showed "inputs changed" only because merging yesterday's recapture PR rewrote the raw files' mtimes (`inputsHash` uses size + mtime). Before recapturing, diff the app's commits since the last build: here 0.16.2 added a headline feature (living lesson cards) that no frame showed, so the run added a frame for it.
- 2026-11-10: `focus` is shared by the iPhone and iPad frames, but the same control sits at different heights on each (Moon School's Up Next card: y≈0.34 on iPhone, ≈0.20 on iPad). Use `hero` or `tilt` when the point moves between devices.
- 2026-11-11: Azan is a web clock in an Android WebView, so its captures came from Playwright, with two traps. First, a 1080×1920 phone shot (ratio 1.78) is silently dropped as "not a phone": phone captures must be taller than 1.8:1, e.g. 390×852 at 3×. Second, the Android status bar covers the top ~6% of the screen, and a web page has no band there, so the city name would be hidden. `azan/e2e/lobby-shots.spec.ts` stretches the page's top row into that band with ffmpeg; copy it for any web-built app. The icon must be ≥ 1024: render the app's SVG full-bleed (no corner radius, no alpha).
- 2026-11-11: 18-0 showed "inputs changed" because the owner moved its brand to Turf in `store/lobby.json` after the last build. When the captures haven't changed, rebuild and push; there's no need to recapture.
- 2026-11-11: The review watcher died on 2026-11-09 and nobody noticed for two days. launchd's login shell found `/usr/local/bin/node` (v16), which can't run the extensionless ES-module script (`ERR_UNKNOWN_FILE_EXTENSION`). install.sh now pins an absolute Node >= 22 in the plist. A dead watcher also stalls the Stage Manager agreement window, so check `~/.cache/lobby/review.log` when `/cue/api/agreement` stops counting.
- 2026-11-12: Hinge Pop showed "inputs changed" only for a recorded app id, but main had moved from 0.1.x to 0.3.0 and a frame still said "50 levels" (the app has 800). A locked version doesn't make old copy safe: staged frames go up on the *next* version. Read the release notes since the last build and recapture when the copy has gone stale.
- 2026-11-12: 18-0's "Sixty years deep" badge sat for a week while the app's own home screen says 1980–2025. Check every number in a caption against what the captures show.
- 2026-11-12: When a raw folder holds `1-modes.jpg` and `1-modes.png`, the sorted listing makes the `.jpg` win. 18-0 keeps old web PNGs gitignored beside its new simulator JPEGs; that's why.
- 2026-11-13: Hinge Pop's new villain frame went `bleed` first, and the caption panel hid the three villains along the bottom of the screen. A capture whose point fills the whole screen (a lineup, a field of enemies) needs `hero`, so the full device shows under the title.
- 2026-11-14: The `tilt` badge also sits at a fixed spot, low on the left. On 18-0's iPad lineup frame it covered the WR1 card, while the iPhone frame was fine, because the iPad field is taller. When a frame's point is a full lineup or grid, drop the badge and put its fact in the sub. Also: Hinge Pop showed "inputs changed" again only from the mtimes left by merging a raw capture (villain.png). The manifest and the iOS code hadn't changed, so the run rebuilt, looked and staged it without a recapture.
- 2026-11-19: COLD GAS showed "inputs changed" because the app's own 0268 shoot (Nov 16) replaced the raws, but 0292 then redrew every vehicle (Nov 18) and those raws still showed the retired wedge car and lattice rocket, the very look 0292 dropped as an IP risk. A fresh capture can go stale within days: before building, grep the app's backlog and release notes for shipped visual changes newer than the raws' commit. Also, a shot with no capture for a device falls back to another device's raw (the iPad's editor frame showed an iPhone screen), so read the iPad row of the sheet for phone-shaped screens.
- 2026-11-20: Yesterday's COLD GAS reshoot (PR #457) went stale before it merged. It was shot at 16:00, and the 1.2.0 world train (water, real sky, tanks on the sets) merged at 22:44. Its CI then timed out, so auto-merge never fired. When a `lobby/*` PR is still open, check what has merged into main since its captures before rebuilding. Two more traps from that run. First, `lobby build <slug>` builds the main checkout, because discovery skips worktrees. Build and push a worktree by path: `lobby build ~/Desktop/projects/<app>-lobby`. Second, the target's 10-shot cap was applied to the manifest's list before shots without a capture for that device were dropped. An 11th shot (the new iPhone/iPad water frame) pushed the Duo-only tabletop frame out of the Duo set. `render` now caps after filtering. (In an ad hoc zsh loop, `$args` doesn't word-split, and the app ignored the flags; use `${=args}` or a bash script.)
- 2026-11-22: The first keyer replaced the green ferns behind a hand-held phone (Mixkit 45345) along with its screen. The tracker now scores contours by phone shape and the key is clipped to the tracked quad. Lobby's own preview for Hearth was also found truncated (48 bytes, header only) from the 2026-11-21 run.
- 2026-11-22: LTX-2.3 rendered "chroma green" screens as lime or mint at about 35 levels above the other channels, under the keyer's old 40 threshold, so three shots kept their green. The keyer now accepts hue 30–90 and a 22-level margin, clipped to the tracked device.
- 2026-11-22: Asked twice for an unmarked field, LTX still painted end-zone lettering that read like a real school, a midfield emblem and scoreboards. For apps that forbid marks, check every generated frame and drop the shot rather than crop around it.
- 2026-11-22: The ltx-2.3-mlx-q8 repo is ~82 GB, not the 26 GB its card suggests: it carries dev, distilled and distilled-1.1 transformers plus LoRAs.
